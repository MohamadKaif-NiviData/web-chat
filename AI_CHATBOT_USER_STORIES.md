# AI Chatbot (Ollama) — User Stories

Scope: the standalone "Chat with AI" feature described in
`AI_CHATBOT_PLAN.md`. This captures the *requirements* in Given/When/Then
form — for the technical plain-English build plan (which file does what, in
what order), see `AI_CHATBOT_PLAN.md` itself.

**Actors**:
- **User** — a logged-in participant of the chat app.
- **System** — the backend (FastAPI `POST /ai/chat`) and the self-hosted
  Ollama container running `llama3`.

---

## Story 1 — Start a new AI chat

As a logged-in user, I want a clearly separate entry point for talking to
the AI so it never gets mixed into my regular 1-to-1/group conversations.

```gherkin
Scenario: Opening the AI chat for the first time
  Given I am logged in and on the chat list page
  When I click "Chat with AI"
  Then a separate chat box opens on its own page
    And it starts empty — no messages from any previous session, mine or anyone else's
```

## Story 2 — Send a message and get a real AI reply

```gherkin
Scenario: Sending a message
  Given I am on the AI chat page
  When I type a message and send it
  Then my message appears in the chat immediately
    And after a short wait, a reply generated by the llama3 model appears
    And the reply is an actual model-generated response, not an echo of my own message
```

## Story 3 — See a "thinking" state while waiting

Model inference can take anywhere from a few seconds to tens of seconds on
CPU-only hardware — the UI must not look frozen or broken during that wait.

```gherkin
Scenario: Waiting for a reply
  Given I just sent a message
  When the backend is still waiting on Ollama to generate a response
  Then the chat visibly shows a "thinking" / loading state
    And sending another message is disabled until the current reply resolves
```

## Story 4 — The AI remembers earlier messages in the same session

```gherkin
Scenario: Asking a follow-up question
  Given I have already sent at least one message and received a reply
  When I send a follow-up message that only makes sense with that earlier context
    (e.g. "what did I just ask you?")
  Then the AI's reply shows it has the earlier message as context
    And this works because the frontend resends the entire message history with
      every request — the backend itself holds no memory of the conversation
```

## Story 5 — Chat history does not survive a refresh

This is a deliberate scope decision for this version (see
`AI_CHATBOT_PLAN.md`), not a bug to be fixed later.

```gherkin
Scenario: Refreshing the page
  Given I have an ongoing AI chat with several messages
  When I refresh the page, or navigate away and back
  Then the chat box is empty again
    And no record of the conversation exists anywhere in the database
```

## Story 6 — Only logged-in users can reach the AI

```gherkin
Scenario: Calling the AI chat endpoint without authentication
  Given I do not have a valid access token
  When a request is made to POST /ai/chat
  Then the request is rejected with 401
    And no call is ever made to the Ollama container
```

## Story 7 — Graceful failure when the AI model is unavailable

```gherkin
Scenario: The Ollama container is stopped or unreachable
  Given the Ollama container is not running, not reachable, or still loading the model
  When I send a message in the AI chat
  Then I see a clear, readable error in the UI — not a silent hang, not a raw stack trace
    And the backend logs a handled error (e.g. a clean 502), never an unhandled traceback
```

## Acceptance notes (non-functional, cross-cutting)

- **Authentication**: identical bar to every other protected route in this
  app — a valid logged-in session is required, no anonymous access, no
  separate auth scheme invented for this feature.
- **Isolation from the existing chat system**: no `Conversation`,
  `Participant`, or `Message` row is ever created or touched by this
  feature. It cannot appear in the regular chat list, and nothing here
  changes behavior for 1-to-1/group chats.
- **Known, accepted limitations** (carried over from `AI_CHATBOT_PLAN.md` —
  explicitly out of scope for this version, not oversights):
  - **No streaming** — a reply arrives as one complete block once the model
    finishes, not token-by-token.
  - **No history cap** — a long enough session resends an ever-growing
    message array on every turn, so both request size and latency grow
    over the life of a session.
  - **No concurrency handling** — if two people use the AI chat at the same
    time, Ollama generally processes one inference at a time; the second
    request simply waits longer rather than running in parallel.
  - **No persistence across devices, sessions, or logout** — by design, per
    Story 5.
